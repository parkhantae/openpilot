# 버튼·프리셋 상세 설정

[English](../en/buttons-presets.md)

> [!NOTE]
> 이 문서는 `carrot-wip` 코드와 함께 관리하는 사용자 설명서 원본입니다. 사용자 동작이 바뀌면 관련 코드·테스트와 같은 변경에서 이 문서도 갱신합니다.

이 페이지는 `carrot-wip`의 실제 코드를 기준으로 **버튼·프리셋 15개 설정**을 설명합니다. 설정 화면의 짧은 문구만으로 알기 어려운 짧게 누르기·길게 누르기·사용자 모드의 차이와 순정 SCC 버튼 스팸의 적용 조건을 함께 정리했습니다.

모든 값은 Carrot Web의 **설정 → 주행 제어 → 버튼·프리셋**에서 변경합니다.

> [!CAUTION]
> 버튼 이벤트와 순정 SCC 메시지 구성은 차종마다 다릅니다. 반드시 현재 값을 기록하고, 안전하게 정차한 상태에서 버튼 인식부터 확인하세요. 주행 중에는 한 항목씩만 변경하고 예상과 다르면 즉시 일반 모드로 복원하세요.

## 먼저 알아둘 핵심

- 아래 동작은 차량 인터페이스가 해당 버튼 이벤트를 정상 전달할 때만 적용됩니다.
- 짧게 누르기와 길게 누르기는 같은 속도 단위를 쓰지 않습니다. 현재 코드에서 **길게 누르기는 항상 10km/h 격자**입니다.
- 사용자 모드 1~3에서는 `CruiseSpeedUnitBasic`보다 `CruiseSpeedUnit`의 영향이 커집니다.
- 크루즈가 꺼져 있거나 대기·정차·브레이크 복귀 상태이면 속도 변경보다 크루즈 재개 로직이 우선할 수 있습니다.
- mph 화면에서는 짧게 누르기 단위를 mph로 해석해 내부 km/h로 변환하지만, 길게 누르기의 고정 10은 내부 km/h 기준이므로 약 6.2mph씩 움직입니다.

### 초기값이 서로 다르게 보일 수 있습니다

Carrot Web의 개별 기본값 복원은 `carrot_settings.json`의 `default`를 사용하고, Params가 처음 만들어질 때는 `params_keys.h`의 초기값을 사용합니다. 현재 브랜치에는 다음 차이가 있습니다.

| 파라미터 | 설정 카탈로그 기본값 | Params 최초값 |
|---|---:|---:|
| `PaddleMode` | 1 | 0 |
| `CruiseSpeedUnitBasic` | 10 | 1 |
| `CruiseButtonTest1` / `2` / `3` | 0 / 0 / 0 | 8 / 30 / 1 |
| `CruiseSpeed1`~`5` | 10 / 10 / 10 / 10 / 10 | 30 / 50 / 80 / 110 / 130 |

특히 버튼 테스트의 카탈로그 기본값 `0`은 화면 최소값보다도 작습니다. 숫자를 억지로 통일하지 말고 **내 장치의 현재 값**을 기준으로 백업한 뒤 조정하세요.

<a id="button-modes"></a>
## 1. 버튼 모드

관련 설정은 `CruiseButtonMode`, `CancelButtonMode`, `LfaButtonMode`, `PaddleMode`입니다.

### `CruiseButtonMode`

아래 표는 크루즈가 이미 활성화되고 일반 주행 중일 때의 짧게 누르기 기준입니다.

폭스바겐의 별도 `SET`은 현재 계기판 속도로 설정하고, `RES`는 브레이크 전 저장속도가 있으면 그 값을 복원하며 없으면 기존 설정속도를 유지합니다. 아직 설정속도를 초기화하지 않았다면 `RES`도 현재 속도를 사용하고, 최종 속도에는 기존 최저·최고 설정속도 제한이 적용됩니다.

`SET`·`RES`는 짧게 또는 길게 눌러도 놓을 때 한 번만 처리합니다. 아래 버튼 모드·속도 단위·길게 누르기 설정은 별도 `+`·`-`에 적용되며, 순정 SCC에서 속도를 가져오는 경우에는 순정 설정속도가 우선합니다.

오픈파일럿 종방향 제어의 수동 인게이지는 기존처럼 물리 `SET`·`RES`를 놓을 때 요청합니다. 단순 `+`·`-` 버튼을 인게이지 버튼으로 추가하지 않습니다.

| 값 | 가속(RES/+) 짧게 | 감속(SET/-) 짧게 |
|---:|---|---|
| 0 일반 | `CruiseSpeedUnitBasic`의 다음 격자 | `CruiseSpeedUnitBasic`의 이전 격자 |
| 1 사용자1 | 30km/h 미만이면 30, 이후 `CruiseSpeedUnit` 간격의 다음 속도 | `CruiseSpeedUnit`의 이전 격자 |
| 2 사용자2 | 사용자1과 같음 | 현재 차속으로 맞추거나 조건에 따라 당근 크루즈 진입 |
| 3 사용자3 | `CruiseSpeed1`~`5` 중 현재 설정속도보다 큰 첫 값 | 사용자2와 같음 |

사용자1~3의 가속 버튼은 현재 설정속도가 30km/h 미만이면 먼저 30km/h로 올리고, 그 이후에는 40km/h부터 `CruiseSpeedUnit` 간격으로 다음 값을 찾습니다. 사용자3은 프리셋을 모두 지난 다음에만 `CruiseSpeedUnit` 격자로 이어집니다.

사용자2·3의 감속 버튼은 단순히 일정 값을 빼는 모드가 아닙니다.

- 실제 차속이 설정속도보다 충분히 높으면 설정속도를 실제 차속 쪽으로 맞춥니다.
- 실제 차속이 설정속도보다 낮으면 실제 차속으로 낮출 수 있습니다.
- 더 낮출 조건이 없으면 당근 크루즈 상태로 들어갈 수 있습니다.

단순한 `+1/-1` 또는 `+10/-10` 동작이 필요하면 먼저 `CruiseButtonMode=0`에서 확인하는 것이 좋습니다.

### `CancelButtonMode`

| 값 | 캔슬 버튼 짧게 |
|---:|---|
| 0 | 크루즈 캔슬 상태로 전환하고 횡제어는 유지 |
| 1 | 크루즈 캔슬과 함께 횡제어도 해제 |

캔슬 버튼을 **길게 누르면 모드와 관계없이 횡제어까지 해제**합니다. 짧게 눌렀는데 조향까지 꺼지는 것이 싫다면 `0`, 캔슬 한 번으로 모두 해제하려면 `1`의 동작을 확인하세요.

### `LfaButtonMode`

| 값 | LFA 버튼 짧게 |
|---:|---|
| 0 일반 | 횡제어 켜기·끄기 |
| 1 감속정지 & Ready | 자동 감속·Ready 흐름 활성화 |
| 2 당근 크루즈 | 당근 크루즈 활성화 |

`1`은 누르는 즉시 고정 감속을 명령하는 설정이 아닙니다. 내부의 패들 감속 대기 상태를 켜고, 이후 정지·선행차·크루즈 상태에 따라 Ready와 재활성화 흐름을 처리합니다. 현재 코드에도 수정 필요 주석이 남아 있으므로 실험 기능으로 보고 충분히 검증하세요.

LFA 버튼을 **길게 누르면** `LfaButtonMode`와 무관하게 레인모드 적용 속도 기능을 임시로 켜거나 끕니다.

### `PaddleMode`

| 값 | 패들 입력의 현재 코드 동작 |
|---:|---|
| 0 | 별도 패들 동작을 처리하지 않음 |
| 1 | 크루즈 OFF 후 Ready |
| 2 | 크루즈 OFF 후 Ready + 자동 감속 상태 |
| 3 | 당근 크루즈 활성화 |

> [!IMPORTANT]
> 설정 카탈로그 설명에는 `0: 크루즈ON`이라고 적혀 있지만, 현재 실행 코드는 `PaddleMode > 0`일 때만 패들 분기로 들어갑니다. 따라서 현재 브랜치에서 `0`은 사실상 **패들 기능 미사용**으로 해석해야 합니다.

패들 이벤트를 전달하지 않는 차종에서는 값을 바꿔도 반응하지 않습니다. 좌·우 패들은 현재 같은 모드 동작을 사용합니다.

### 길게 누르기의 공통 동작

| 버튼 | 길게 누를 때 |
|---|---|
| 가속·감속 | 설정속도를 다음·이전 10km/h 격자로 변경하고 누르는 동안 반복 |
| 차간 | `MyDrivingMode`를 연비 → 안전 → 일반 → 고속 순서로 전환 |
| LFA | 레인모드 속도 적용을 임시 켜기·끄기 |
| 캔슬 | 크루즈 캔슬과 횡제어 해제 |

<a id="speed-units"></a>
## 2. 속도 단위

### 어떤 설정이 어디에 쓰이나요?

| 설정 | 범위 | 실제 역할 |
|---|---:|---|
| `CruiseSpeedUnitBasic` | 1~100 | 일반 모드에서 짧게 누르는 가속·감속의 기본 격자 |
| `CruiseSpeedUnit` | 1~100 | 사용자1~3의 확장 속도 격자, 감속 단위, 프리셋 이후 가속 단위 |
| `CruiseButtonLongDelay` | 30~100 | 가속·감속 버튼을 길게 눌렀다고 판단할 때까지의 제어 프레임 수 |

`CruiseSpeedUnitBasic=1`이면 일반 모드에서 1km/h 단위, `5`이면 5km/h 격자, `10`이면 10km/h 격자로 이동합니다. 현재 값이 격자 사이에 있으면 단순히 현재 값에 더하는 대신 올림·내림하여 다음 격자에 맞춥니다.

예를 들어 일반 모드, 기본 단위 5, 설정속도 83km/h라면:

- 가속 짧게: 85km/h
- 감속 짧게: 80km/h

### `CruiseButtonLongDelay`는 초가 아니라 프레임입니다

버튼 처리는 약 100Hz 제어 주기에서 실행되므로 다음처럼 이해할 수 있습니다.

| 저장값 | 가속·감속 길게 판정 | 차간·LFA·캔슬 길게 판정 |
|---:|---:|---:|
| 30 | 약 0.30초 | 약 0.60초 |
| 40 | 약 0.40초 | 약 0.70초 |
| 60 | 약 0.60초 | 약 0.90초 |

차간·LFA·캔슬은 내부적으로 설정값에 30프레임을 더합니다. 실제 버튼 메시지 주기와 차량 인터페이스에 따라 체감 시간은 조금 달라질 수 있습니다.

> [!NOTE]
> `CruiseSpeedUnit`이나 `CruiseSpeedUnitBasic`을 바꿔도 길게 누르기의 10km/h 반복 단위는 바뀌지 않습니다.

### 추천 확인 순서

1. `CruiseButtonMode=0`으로 둡니다.
2. `CruiseSpeedUnitBasic=1`에서 짧게 누르기를 확인합니다.
3. 길게 누르기 판정만 `CruiseButtonLongDelay`로 맞춥니다.
4. 그 다음 사용자 모드와 `CruiseSpeedUnit`을 시험합니다.

## 3. 버튼 테스트·스팸

`CruiseButtonTest1`~`3`은 운전자의 버튼 감도를 바꾸는 일반 설정이 아닙니다. openpilot이 **현대·기아 순정 SCC의 설정속도를 목표값과 맞추기 위해 가상 RES/SET 버튼 메시지를 보낼 때** 사용하는 고급 값입니다.

| 설정 | Params 최초값 | 역할 |
|---|---:|---|
| `CruiseButtonTest1` | 8 | 한 번의 묶음에서 허용할 연속 전송 횟수 |
| `CruiseButtonTest2` | 30 | 묶음 전송 후 또는 운전자 버튼 입력 후 쉬는 프레임 수 |
| `CruiseButtonTest3` | 1 | CAN FD 경로에서 허용된 한 번의 전송을 몇 개 메시지로 복제할지 |

포터2 EV 일반 크루즈 전용 경로에서는 `CruiseButtonTest1 × 0.01초`를 누름 시간으로 사용하되 0.04~0.06초로 제한합니다. `CruiseButtonTest2 × 0.01초`는 다음 요청까지의 최소 간격이며 0.3초 이상입니다. `CruiseButtonTest3`는 이 경로에 사용하지 않습니다. 신선한 순정 CLU11 수신마다 한 번만 송신하고 해제 메시지 두 번을 보낸 뒤 순정 설정 속도의 변화를 기다립니다. 0.5초 동안 응답이 없으면 최소 0.5초를 쉰 뒤 다시 시도합니다. 연속 세 번 응답이 없으면 3초 이상 쉬고 새 묶음으로 재시도하며, 순정 설정 속도가 요청 방향으로 바뀌면 무응답 횟수를 초기화합니다. 목표값의 변동만으로 진행 중인 누름을 끊지 않으며, 순정 응답이나 운전자 개입 시에는 일찍 해제할 수 있습니다. 자동 제동·정차·차간거리 유지 기능이 아닙니다.

포터 일반 크루즈는 목표와 순정 설정 속도의 차이가 1km/h 미만이면 새 버튼 입력을 시작하지 않습니다. 소수점 목표가 반올림 경계에서 흔들릴 때 불필요한 짧은 입력이 생기는 것을 줄이기 위한 조건이며, 1km/h 이상의 변화에는 추가 대기 시간을 넣지 않습니다. 실차 로그의 정상 응답이 35~56ms였으므로 무응답 확인 시간을 0.5초로 제한해 누락된 입력을 더 빨리 재시도합니다. 기존 페달·기어·신호 유효성 조건은 유지합니다.

포터의 자동 버튼 누름에는 40~60ms 시간 제한과 신선한 CLU11 2~3프레임 송신 횟수 제한을 함께 적용합니다. 같은 수신 샘플을 반복 처리해도 횟수를 소모하지 않습니다. 실행 지연이나 소수점 시간 계산으로 네 번째 누름 프레임이 추가되는 것을 막습니다. 정상 누름 후에는 해제 프레임 두 개를 보냅니다. 이는 출력 펄스의 상한을 보장하는 수정이며 순정 ECU의 수락을 보장하지는 않습니다. 세 프레임 누름에서도 무응답 사례가 확인됐습니다.

자동 SET- 감속 요청 후 RES+ 가속으로 전환할 때는 순정 설정속도보다 1km/h 이상 높은 목표가 0.5초 연속 유지되어야 합니다. 목표가 낮아지거나 페달·유효하지 않은 입력·관측 공백이 생기면 확인 시간을 다시 셉니다. 기존 해제·응답 대기 중에도 확인하므로 대기 시간을 단순 합산하지 않습니다. 추가 SET- 감속, 최초 가속 및 가속 전환 후의 연속 RES+ 간격은 기존대로 유지합니다. 수동 버튼이나 크루즈 해제 시 전환 상태를 초기화합니다. 짧은 목표 변동 직후의 가속 전환을 줄이는 기능이며 레이더 검출을 필터링하거나 직접 제동하지는 않습니다.

버튼 요청 후 0.5초 동안 설정속도 응답이 없으면 다음 요청부터 송신 시점을 바꿉니다. 연속 3회 무응답 뒤에는 기존 3초 대기를 유지합니다. 신선한 순정 CLU11 수신 직후와 그로부터 10ms 대기한 시점을 번갈아 사용합니다. 수신 샘플당 송신은 여전히 최대 한 번이며, 지연 시점에서는 다음 제어 주기에 같은 수신 샘플을 한 번 사용할 수 있습니다. 지연 송신 기회를 100ms 동안 얻지 못하면 기본 시점으로 복귀합니다. 자동 요청 후 순정 설정속도가 요청 방향으로 변한 경우에만 성공 시점을 기억합니다. 같은 제어 프로세스가 실행되는 동안 수동 버튼 또는 크루즈 해제 후에도 마지막 성공 시점을 다시 사용합니다. 이때 자동 누름은 중단하고 진행 중인 요청을 지우며 기존 재개 대기시간을 유지합니다. 실패한 시험이나 수동 버튼 응답은 성공 시점을 덮어쓰지 않습니다. 성공 이력이 없으면 기본 시점을 사용하고 제어 프로세스를 재시작하면 기억을 초기화합니다. 이후 무응답이 생기면 다음 요청에서 다른 시점을 시도합니다. 운전자 취소와 페달 개입에 따른 중단에는 이 추가 지연을 적용하지 않습니다. 메시지 내용·카운터·누름 상한·재시도 빈도는 바꾸지 않습니다. 지속 무응답에 대한 재시도 타이밍 시험이며 순정 ECU의 거부 원인이나 해결을 확정한 것은 아닙니다. `PorterButtons` 진단의 `delay_ms`에 현재 시점을 기록합니다.

### 포터 순정 하한 미만 목표 자동 취소

Carrot Web > 설정 > 차량·하드웨어 > 포터 전용에 **포터: 목표 30km/h 미만 크루즈 취소** (`PorterAutoCancelBelow30`)를 추가했습니다. 기본 OFF이면 기존 버튼 가감속 동작을 유지합니다. ON은 포터2 EV의 `SpeedFromPCM=0`에서만 적용하며 변경 즉시 반영합니다. 30km/h 하한으로 제한하기 전의 유효한 계획·운전자 선택·내비·기존 근접 앞차 제한 목표를 확인합니다. 30km/h 미만 목표가 0.3초 연속 유지되면 순정 크루즈 취소를 요청하고 순정 OFF 확인까지 재개 요청을 막습니다. 무효·오래된 신호나 짧은 목표 변동으로 새 취소를 시작하지 않습니다. OFF로 바꾸면 이 기능의 대기·취소 상태를 지우지만 크루즈를 다시 켜지 않습니다.

실제 차량 속도나 앞차 거리만을 기준으로 취소하지 않습니다. 취소는 순정 크루즈를 해제하라는 요청이며 브레이크 제동·정차 명령이 아닙니다. 자동 재시작 기능은 추가하지 않았습니다. 이 선택 기능의 실차 응답 검증은 아직 필요합니다.

차간시간은 공통 TF1~TF4(`TFollowGap1`~`TFollowGap4`) 한 곳에서 설정합니다. 포터의 버튼 감속과 선택적 저속 자동 취소는 플래너의 속도·주행·감속 보정이 반영된 실제 추종시간을 함께 사용합니다. 신선하고 유효한 플래너 값이 없으면 선택한 단계의 공통 TF 기본 설정을 사용합니다. 기존 포터 전용 GAP 저장값은 읽거나 공통 TF로 복사하지 않습니다. 판단 거리의 최소 7m와 기존 버튼·취소 제한은 유지하며 실제 차간거리·제동을 보장하지 않습니다.

2024 포터2 EV 순정 크루즈의 확인된 설정속도 하한은 30km/h입니다. 핸들 버튼 대행은 순정 ECU의 하한을 바꿀 수 없으므로 콤마 목표속도, 순정 설정속도 상태, 버튼 송신 및 panda 허용 조건에 같은 30km/h 하한을 적용합니다. 차량 실제 속도는 감속 중 30km/h 아래로 내려갈 수 있지만, 순정 크루즈 설정속도를 29km/h 이하로 지정하거나 그 속도를 유지하지는 못합니다.

포터에서 `SpeedFromPCM=0`을 사용하면 과속카메라 접근 중 내비가 계산한 현재 감속 목표와 종방향 플래너 목표 중 낮은 값을 순정 버튼 목표로 사용합니다. 따라서 먼 지점의 플래너 속도가 더 높아도 카메라 감속 목표가 버튼에 반영됩니다. 30km/h 이상에서는 1km/h 단위로 계기판 설정속도를 맞추며, 20km/h 제한처럼 순정 하한보다 낮은 목표는 30km/h까지만 낮춥니다.

포터의 비전 앞차 제어는 선택한 차간 단계와 8초 뒤 예상 거리를 확인합니다. 앞차와의 간격이 선택값보다 작아질 것으로 예상되면, 순정 설정속도를 앞차 속도까지 1km/h 단위 SET 입력으로 미리 낮춥니다. 앞차 신호가 0.6초 이내로 잠깐 끊기면 마지막 거리와 상대속도로 계속 접근을 계산합니다. 추적 중인 앞차가 0.5초 동안 계속 멀어지는 것이 확인되기 전에는 RES+로 순정 설정속도를 올리지 않아, 비전 상대속도가 잠깐 튈 때 저장된 속도가 복원되는 것을 막습니다. 이는 일반 크루즈의 가속을 더 일찍 줄이는 방식이며 브레이크를 직접 작동하거나 안전한 차간을 보장하지 않으므로, 감속이 부족하면 운전자가 즉시 브레이크를 밟아야 합니다.

제어 주기가 약 0.01초이므로 `CruiseButtonTest2=30`은 대략 0.30초의 휴지 프레임에 해당합니다. 다만 순정 설정속도가 실제로 변한 것을 감지하면 코드는 별도의 7프레임 대기를 사용하기도 합니다.

적용 범위를 구분해야 합니다.

- 현대·기아 비롱컨 구성의 순정 SCC 속도 동기화에서 사용됩니다.
- 일반 CAN과 CAN FD 버튼 경로 모두 `Test1`, `Test2`의 영향을 받을 수 있습니다.
- `Test3`의 메시지 복제는 현재 CAN FD 전송 경로에서 사용됩니다.
- `SpeedFromPCM=1`이면 목표와 순정 설정속도의 차이를 맞추는 RES/SET 스팸 분기가 동작하지 않습니다.
- `SpeedFromPCM` 기본값은 `2`(커브·카메라 감속)입니다. 설정의 기본값 복원도 `2`를 사용하며, 기존에 저장된 값은 업데이트만으로 바뀌지 않습니다.
- 차종이 이 버튼 전송 경로를 쓰지 않으면 세 값을 바꿔도 효과가 없습니다.

> [!WARNING]
> 값을 크게 올리면 버튼 메시지가 과도하게 전송되거나 순정 SCC가 입력을 놓치고, 반대로 너무 작으면 목표 속도 동기화가 늦거나 실패할 수 있습니다. 문제가 없다면 Params 최초값 `8 / 30 / 1`을 유지하세요.

### 토요타·렉서스의 순정 설정속도

`SpeedFromPCM=3`에서는 순정 SET/RES 설정속도를 카롯의 기본 목표속도로 사용합니다. `1`도 순정 설정속도를 사용하며, `0`과 `2`는 기존 카롯 속도 선택을 유지합니다. 이 설정은 순정 ACC와 openpilot 가감속 사이를 전환하거나 레이더를 켜고 끄지 않습니다. openpilot 가감속 사용 시 앞차·커브·카메라 감속은 이 기본 목표보다 낮게 적용될 수 있습니다.

`0`의 예외로, `TOYOTA_RAV4_TSS2_2022`에서 PCM과 openpilot 직접 가감속을 함께 사용할 때는 유효한 CAN으로 관측한 순정 설정속도 변경과 크루즈 비활성→활성 전이를 기본 목표에 반영합니다. 처음부터 활성인 표본은 기준만 저장하며, 같은 주기의 로컬 버튼·블루투스 속도 변경이 우선합니다. 낮은 앞차·커브·지도 감속 목표는 계속 적용되고, RES/SET CAN 송신을 추가하지 않습니다.

## 4. 속도 프리셋

`CruiseSpeed1`~`CruiseSpeed5`는 `CruiseButtonMode=3`에서 가속 버튼을 짧게 눌렀을 때 사용하는 순서형 속도 테이블입니다.

| 설정 | Params 최초값 | 권장 역할 예시 |
|---|---:|---|
| `CruiseSpeed1` | 30 | 저속·생활도로 |
| `CruiseSpeed2` | 50 | 일반 시내도로 |
| `CruiseSpeed3` | 80 | 자동차전용도로 |
| `CruiseSpeed4` | 110 | 고속도로 |
| `CruiseSpeed5` | 130 | 마지막 사용자 단계 |

이 역할 이름은 이해를 돕기 위한 예시이며 법정 제한속도나 권장 주행속도를 뜻하지 않습니다. 실제 값은 지역·도로·차량 조건에 맞춰야 합니다.

### 선택 방식

코드는 1번부터 5번까지 차례로 읽고 **현재 설정속도보다 큰 첫 값**을 선택합니다. 프리셋을 모두 지났으면 `CruiseSpeedUnit`의 다음 격자로 이동합니다.

예를 들어 `30 / 50 / 80 / 110 / 130`, 현재 76km/h이면 짧은 가속 한 번으로 80km/h가 됩니다. 다시 누르면 110km/h가 됩니다.

프리셋은 자동 정렬하지 않으므로 반드시 작은 값부터 큰 값 순서로 저장하세요. 중복되거나 역순이면 일부 단계가 건너뛰어질 수 있습니다.

### `CruiseSpeed1=0`의 특별 동작

1번만 `0`을 허용하며, 이때 고정 0km/h가 아니라 현재 도로 제한속도를 이용해 동적으로 만듭니다.

- `AutoRoadSpeedLimitOffset >= 0`: 도로 제한속도 + 오프셋
- `AutoRoadSpeedLimitOffset < 0`: 도로 제한속도 × `AutoNaviSpeedSafetyFactor`

예를 들어 제한속도 60km/h, 오프셋 5이면 65km/h가 되고, 오프셋 -1과 안전비율 105%이면 63km/h가 됩니다. 유효한 도로 제한속도 정보가 들어오지 않으면 기대한 프리셋이 만들어지지 않습니다.

### 안전하게 구성하기

1. 먼저 `30 / 50 / 80 / 110 / 130`처럼 확실한 오름차순으로 시험합니다.
2. 마지막 프리셋 다음 동작을 결정하는 `CruiseSpeedUnit`도 함께 기록합니다.
3. `CruiseSpeed1=0`은 도로 제한속도와 오프셋이 정상 수신·적용되는 것을 확인한 뒤 사용합니다.
4. 사용자3의 감속 버튼은 프리셋을 역순으로 내려가지 않는다는 점을 기억하세요.

### 포터 MAIN 대기 자동 SET

설정 > 차량·하드웨어 > 포터 전용의 **포터: MAIN 대기 중 자동 SET** (`PorterAutoSetMain`)은 기본 OFF입니다. ON 변경 후 재시작하면 전용 Panda 설정이 적용되며, 계기판 CRUISE 대기가 켜져 있는지 확인하세요. `AutoEngage=2`의 초기 ON 값은 이 기능의 허가로 사용하지 않습니다. OFF 변경은 즉시 새 요청을 막지만 이미 켜진 순정 크루즈를 취소하지 않습니다.

`SpeedFromPCM=0`을 유지하고, 목표 속도와 계기판 속도가 모두 30~160km/h 범위이며 유효한 계획·레이더 신호가 있어야 합니다. 인게이지 또는 조향 제어가 활성일 때의 기존 대기 경로는 조건을 0.5초 확인한 후 짧은 SET−를 요청합니다. 조향까지 비활성인 MAIN 대기에서도 새 엑셀 밟기·해제마다 RES+가 아닌 SET−를 요청하며, 페달 입력 없이 대기만 해서는 시작하지 않습니다. 순정 OFF에서 최대 6개 프레임/120ms, 요청 간 최소 1초이며 3회 요청 뒤 3초 대기합니다. 페달 가속 중에는 요청하지 않고 조건 확인을 다시 시작합니다. 신호 단절·브레이크·홀드·주차브레이크·CANCEL·MAIN OFF·설정 OFF는 허가를 해제합니다. 브레이크·CANCEL 뒤에는 MAIN ON을 유지한 채 엑셀을 새로 밟아 30km/h 이상에서 놓으면 다시 허용합니다. MAIN OFF에서는 시작하지 않습니다.

30km/h 미만 자동 취소를 함께 켜면 해당 기능으로 꺼진 뒤에도 MAIN 허가는 유지되어 같은 조건에서 SET−로 재시작합니다. 계기판 속도가 30km/h 미만이면 재시작하지 않으므로 운전자가 가속해야 합니다. 설정시간은 실제 차간거리 보장이 아니며 직접 제동·정차·정지 상태 자동 출발은 제공하지 않습니다. SET은 현재 주행속도로 순정 크루즈를 시작하며, 이후 기존 버튼 제어가 목표를 맞춥니다. 이 자동 SET 경로의 실차 수락 여부는 아직 검증하지 않았습니다.


순정 크루즈 OFF로 인게이지가 풀리고 조향도 비활성이어도, MAIN 대기에서 새 엑셀 밟기·해제와 나머지 조건을 확인하여 SET을 판단합니다. 수동 SET 등으로 순정 크루즈가 실제 켜지면 MAIN 추적값만 ON으로 동기화하며, 브레이크·CANCEL로 해제된 허가는 복구하지 않습니다. MAIN OFF 직후 늦게 남는 ON 피드백은 다시 허용하는 근거로 쓰지 않습니다.

자동 취소는 최대 3프레임/60ms의 CANCEL 누름과 명시적 해제를 사용합니다. OFF를 확인하지 못하면 해제 후 0.5초 기다려 다시 시도하고, 3회 요청 후에는 3초 쉽니다. 성공했던 송신 슬롯부터 사용하고 무응답이면 0/10ms 슬롯을 번갈아 시도합니다. 취소 중에는 SET/RES를 막고 운전자 버튼이 우선합니다. TX echo만으로 취소 성공을 판단하지 않습니다. 이 수정의 실차 취소·SET 수락은 아직 검증되지 않았습니다.


MAIN 허가가 유지되는 대기 상태에서 엑셀로 30km/h 이상 가속한 뒤 놓으면, 목표·계기판 속도 조건이 유효한 경우 추가 해제 확인시간 없이 다음 송신 가능한 CAN 주기에 SET−를 요청합니다. MAIN 허가 후 최소 0.5초와 기존 재시도 간격은 유지합니다. 순정 SET은 차량이 수락하는 시점의 실제 속도로 켜지므로 페달을 놓은 순간의 속도를 정확히 고정하는 명령은 아닙니다. 이후 기존 목표 속도 가감속은 계속 적용합니다. 브레이크·CANCEL·무효 신호 및 30km/h 미만 목표를 우회하지 않습니다.

브레이크·CANCEL 이후 새 엑셀 입력을 0.1초 이상 확인하고, 목표·계기판 속도가 모두 30km/h 이상인 유효한 해제 입력에서만 허가를 복구합니다. 유효한 해제를 확인하면 추가 대기 없이 SET을 요청하며 기존 누름 제한을 적용합니다. 해제 전부터 계속 밟고 있던 엑셀이나 페달 조작 없는 조건 회복만으로는 재시작하지 않습니다. MAIN OFF, 설정 OFF, 무효 신호·브레이크·홀드·주차브레이크가 남아 있는 경우도 차단합니다.

크루즈 최초 진입 SET은 기존 3프레임/60ms에서 최대 6프레임/120ms로 늘렸습니다. 순정 ON 응답이 오면 남은 누름을 즉시 해제하며, 기존 가감속·CANCEL 누름 제한과 송신 간격은 그대로입니다. 수동 SET 성공 로그의 누름 길이를 참고한 보완이며 순정 ECU 수락을 보장하지 않습니다.

엑셀 해제 순간 앞차·계획 목표로 요청이 잠깐 막히면 해제 이력을 최대 0.1초 보존합니다. 그 안에 조건이 회복되면 추가 확인 대기 없이 다음 송신 가능한 주기에 SET을 요청합니다. 차단이 0.1초를 넘으면 해제 이력을 버리며, 계기판 속도·목표 30km/h 하한이나 브레이크·무효 신호를 우회하지 않습니다.

자동 SET을 켜도 MAIN 추적 초기값을 강제로 OFF로 바꾸지 않습니다. AutoEngage=2이면 CarState·버튼 제어·Panda가 초기 ON 추적값을 함께 사용하며, 그 초기값만으로 자동 SET을 허가하지 않습니다. MAIN 확인 전에는 아래의 새 엑셀 입력으로 한 번의 SET 시도만 허용하며, 실제 순정 ON 응답이 MAIN 추적을 확정합니다. 바퀴 속도·브레이크·CANCEL·MAIN OFF 제한은 유지합니다. 이 값은 순정 MAIN의 절대 상태를 새로 해독하는 기능이 아니므로 계기판과 초기 설정이 다른 경우에는 별도 확인이 필요합니다. 변경 후 재시작이 필요합니다.

순정 크루즈가 꺼진 상태의 자동 SET은 새 CLU11 수신을 관측한 제어 주기에만 송신합니다. 10ms 지연 슬롯은 사용하지 않으며 엑셀 해제·재시도 기한이 수신 사이에 오면 다음 새 수신을 기다립니다. 최대 누름 6프레임/120ms와 요청 간격·브레이크·MAIN 제한은 유지합니다. 주행 중 가감속의 0/10ms 재시도와 성공 시점 기억은 별도로 유지하며 자동 SET이 덮어쓰지 않습니다.

`PorterMainSet` 진단은 요청 수(`req`), 요청 후 0.5초 내 실제 순정 ON 확인 수(`ack`), 무응답 수(`noack`)와 현재 응답 상태를 기록합니다. TX echo만으로 성공을 판단하지 않습니다. 목표 변화로 누름을 해제해도 이미 보낸 요청의 응답은 관측하지만, 운전자 버튼·브레이크·무효 신호는 응답 확인을 중단합니다. 무응답 재시도는 기존 간격과 허가 조건을 지키며 순정 ECU의 수락을 보장하지 않습니다.

페달·목표 변화로 누름이 중단돼도 첫 SET 송신부터 다음 시도까지 최소 1초, 세 번째 시도 뒤에는 3초의 대기를 예약합니다. 반복 엑셀 해제로 이 제한을 우회하지 않습니다.

포터에서는 CANCEL을 길게 눌러 GAP 단계를 바꿉니다. 순정 크루즈 취소도 함께 동작하며 짧게 누르면 기존 취소입니다. 길게 누름 판정시간은 `CruiseButtonLongDelay`를 따릅니다.

`AutoEngage=2`로 재시작한 초기 대기에서 MAIN 확인 이력이 없으면, 엑셀이 놓인 상태를 먼저 관측한 후 새로 0.1초 이상 밟아 30km/h 이상에서 놓을 때 한 번의 SET 시도를 허용합니다. 초기 유효 관측은 0.5초 이상이어야 하며 SET 시작 기회는 해제 후 0.1초 이내입니다. 실패하면 새 페달 입력 없이 반복하지 않습니다. 이미 엑셀을 밟은 채 재시작한 경우에는 먼저 놓았다가 새로 밟아야 합니다.

이 시도는 MAIN의 절대 상태를 판독하는 기능이 아니며 계기판의 CRUISE 대기를 확인해야 합니다. 새 Panda 안전 프로파일도 함께 적용되므로 업데이트 후 재시작이 필요합니다. 기존 프로파일은 이 새 허가를 허용하지 않습니다. `PorterMainSet` 로그는 동작 변화 외에도 1초마다 MAIN 확인·허가·새 페달 관측 상태를 기록합니다.

자동 SET의 30~160km/h 속도 조건은 새 Panda 프로파일에서 계기판 CLU11 속도를 기준으로 판단합니다. 앞왼쪽·뒤오른쪽 바퀴 속도는 각각 25~160km/h이어야 합니다. 둘 다 30km/h 이상이면 기존 바퀴 속도 조건을 적용하며, 어느 하나라도 30km/h 미만이면 두 바퀴 모두 계기판과의 차이가 5km/h 이내인지 추가로 확인합니다. 따라서 계기판 31km/h·바퀴 29km/h는 허용할 수 있지만, 저속·단위 불일치·무효 또는 오래된 신호는 허용하지 않습니다. 목표 30km/h 미만 차단은 그대로이며 변경 후 재시작해 새 Panda 설정을 적용해야 합니다.

포터 버튼 송신은 버튼 상태와 alive 카운터를 바꾼 뒤 해당 필드의 패리티를 다시 계산합니다. 자동 SET·가감속·CANCEL·해제 모두 같은 형식을 사용하며 Panda도 패리티가 맞지 않는 프레임을 차단합니다. 이 정합성 검사는 실제 순정 ON 응답을 대신하지 않습니다.

인게이지·조향이 모두 비활성인 경로는 유효한 엑셀 해제 후 0.1초 안에 시작할 수 있는 요청만 사용합니다. 새 CAN 수신을 기다리되 재시도 제한에 막힌 입력은 나중에 실행하지 않으며, 다시 엑셀을 밟았다 놓아야 합니다. 브레이크·CANCEL 뒤에도 MAIN 대기가 유지되고 새 페달 입력이 유효하면 같은 방식으로 요청합니다. 실제 순정 크루즈의 SET 수락은 별도로 확인해야 합니다.
