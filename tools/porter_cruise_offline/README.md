# 포터2 EV 일반 크루즈 연동 수정안

이 브랜치에는 오프라인 도구와 함께 실제 차량 상태·버튼 제어·panda safety 소스 수정안이 포함되어 있습니다. **Draft입니다. 이전 상태·안전 코드와 펌웨어는 장치에 적용했지만, 새 누름·해제 방식의 차량 명령 수락과 실제 가감속은 미검증입니다.** 기존 오프라인 판단 모델은 참고용으로 남겨 두었고 차량 실행 코드에서 가져오지 않습니다.

## 수정 동작

- `opendbc_repo/opendbc/car/hyundai/porter.py`에서 E_EMS11의 설정 속도와 TCS13의 브레이크 상태를 읽습니다. 필수 메시지의 시간·CAN 유효성·상태 오류를 확인합니다. 확인하지 않은 mph 구성은 비활성 처리합니다.
- 포터는 순정 일반 크루즈의 RES+/SET−로 설정 속도를 조절합니다. 전용 `PorterCruiseButtons`의 제한된 누름·해제·응답 확인 경로로 연결하며, 운전자가 켠 순정 크루즈에서만 작동하도록 제한합니다. 자동 활성화/자동 재개 요청, 페달 개입, 정차, 기어 변경, 오류, 직접 버튼 조작 중에는 속도 버튼을 보내지 않습니다.
- 포터의 직접 종방향 제어와 레이더 ECU 비활성화 경로를 사용하지 않습니다. 일반 크루즈 모드 예외는 정확한 포터 차종·안전 설정에서만 허용합니다.
- 새 `HyundaiSafetyFlags.PORTER_CC=1024`를 EV_GAS와 함께 사용합니다(최종 safetyParam=1025). 이 구성에서만 존재하지 않는 SCC 수신 검사 대신 실제 E_EMS11/WHL_SPD11/TCS13/CLU11/ELECT_GEAR/TCS15를 검사합니다. WHL/TCS 체크섬과 카운터 검사를 유지합니다.
- panda는 최근 물리 버튼 조작과 순정 크루즈 활성 전환을 확인해야 제어를 허용합니다. 가속·감속 버튼은 신선한 필수 수신, D단, 브레이크/가속 페달·홀드·주차브레이크 해제 조건을 요구합니다. 직접 가속·제동·진단 메시지는 허용하지 않습니다. 포터 구성에서는 기존 조향 토크 제한도 강제합니다.

일반 크루즈 속도 설정 조절이며 자동 제동·차간거리 유지·정차 기능은 아닙니다. 포터 전용 소프트웨어 범위는 5~160km/h이며, 제공 기록에서 실제로 확인한 설정 속도는 30~50km/h입니다. 5~29km/h의 차량 수락과 실제 유지 성능은 실차에서 확인해야 합니다. 설정 속도가 최소값에 도달하면 SET−만으로 더 감속할 수 없습니다. `SpeedFromPCM=1`이면 기존 정책에 따라 자동 설정 속도 변경을 하지 않습니다.

`BUILD_REPORT.md`의 기존 F4/H7 해시는 30km/h 하한이던 이전 소스 빌드입니다. 5km/h panda 허용 조건을 적용하려면 이 커밋으로 panda 펌웨어를 다시 빌드하고 호스트 코드와 함께 설치해야 합니다.

## 검증

- 기존 오프라인 판단/후보 디코더 테스트: 15개 통과.
- 실제 포터 상태 및 실제 컨트롤러 함수 테스트: 34개 통과.
- 수정한 C 안전 코드를 호스트 공유 라이브러리로 빌드해 실행한 테스트: 16개 통과.
- 두 첨부 로그를 로컬에서 읽어 상태 복원 및 수정된 C 안전 코드 수신 리플레이를 확인했습니다. 원본 로그·위치·영상·음성·식별 정보는 저장소에 추가하지 않았습니다.
- 두 번째 로그에서 수정된 수신 검사는 초기 약 40ms 이후 정상이며 잘못된 RX 판정은 0개였습니다. 순정 설정 속도가 나타날 때 제어가 허용되고 브레이크 해제 시 차단됩니다. 첫 번째처럼 이미 활성화된 상태로 시작한 기록에서는 자동으로 재활성화하지 않습니다.
- F4/H7 실제 앱·부트스텁 크로스 빌드와 개발용 앱 서명 검증이 완료됐습니다. 상세 버전·해시는 `BUILD_REPORT.md`에 있습니다. 이전 H7 펌웨어는 장치 부팅 갱신 경로로 적용했으며 safetyParam 1025와 P단 브레이크 감지를 확인했습니다. 새 주입 버튼 수락 및 물리적 가감속은 미검증입니다. 로그 리플레이가 폐루프 차량 검증을 대신하지는 않습니다.

저장소 루트에서:

```sh
python -m unittest discover -s tools/porter_cruise_offline -v
python -m unittest discover -s opendbc_repo/opendbc/car/hyundai/tests -p 'test_porter*.py' -v
python -m unittest discover -s opendbc_repo/opendbc/safety/tests -p test_hyundai_porter.py -v
```

네이티브 테스트는 `CC`(기본 `cc`)로 실제 안전 소스 테스트 하니스를 빌드합니다. 준비된 동일 소스의 라이브러리를 사용할 때는 `PORTER_SAFETY_LIB`에 경로를 지정할 수 있습니다. Windows 검증은 GCC 호환 비트필드 설정의 Zig 호스트 빌드와 출력 없는 테스트용 libc 대체 함수를 사용했습니다. 이 테스트 라이브러리와 별도로 실제 F4/H7 펌웨어 크로스 빌드·서명 검증도 완료했습니다.

## 장치 적용 전 남은 확인

이 수정은 Python 파일만 교체해서 적용할 수 없습니다. 새 PORTER_CC 검사를 포함한 panda 펌웨어와 호스트 코드가 함께 필요합니다. 이 저장소의 장치용 전체 빌드와 펌웨어 갱신 경로를 확인한 뒤, 차량 송신/수락 및 페달·취소·신호 유실 동작을 검증해야 합니다. 자동 조향 역시 이 안전 구성에서는 활성 크루즈와 토크 제한을 따르므로 기존 포크의 AlwaysLateral 동작과 같다고 가정하면 안 됩니다.

## 읽기 전용 로그 분석기

```sh
python tools/porter_cruise_offline/inspect_porter_log.py /path/to/rlog.zst
```

`pycapnp`, `zstandard`, 전체 cereal 스키마가 필요합니다. 스키마가 다른 경로에 있으면 `--schema`와 `--car-schema-dir`를 지정합니다. 분석기는 CAN 송신 기능 없이 후보 필드 분포와 기존 상태/송신 종류를 출력합니다.

## 누름·해제 방식 수정

포터2 EV 일반 크루즈 전용 경로에서는 `CruiseButtonTest1 × 0.01초`를 누름 시간으로 사용하되 0.12~0.15초로 제한합니다. `CruiseButtonTest2 × 0.01초`는 다음 요청까지의 최소 간격이며 0.3초 이상입니다. `CruiseButtonTest3`는 이 경로에 사용하지 않습니다. 신선한 순정 CLU11 수신마다 한 번만 송신하고 해제 메시지 두 번을 보낸 뒤 순정 설정 속도의 변화를 기다립니다. 1초 동안 응답이 없으면 최소 0.5초를 쉰 뒤 다시 시도하며, 연속 세 번 응답이 없으면 반복을 중단합니다. 순정 설정 속도가 요청 방향으로 바뀌면 무응답 횟수를 초기화합니다. 최종 차단 후에는 운전자가 크루즈를 해제하거나 실제 버튼을 조작해야 다시 대기합니다. 자동 제동·정차·차간거리 유지 기능이 아니며 차량의 명령 수락은 아직 검증되지 않았습니다.

기존 주행 기록에서는 의도한 버튼 송신 대부분이 panda에서 허용되었으므로, 송신 허용만으로 차량 수락을 판단하지 않습니다. 이전 약 70ms 송신 묶음 대신 관측한 순정 짧은 누름 시간에 맞춘 후보 방식입니다. `PorterButtons: status=... req=... ack=... noack=...` 전환 로그를 남깁니다. 응답은 순정 설정 속도의 요청 방향 변화이며 실제 차량 가감속의 검증을 뜻하지 않습니다.

## 간헐 정지 진단 및 소수점 경계 수정

포터 일반 크루즈는 목표와 순정 설정 속도의 차이가 1km/h 미만이면 새 버튼 입력을 시작하지 않습니다. 소수점 목표가 반올림 경계에서 흔들릴 때 짧은 입력과 무응답 잠금이 생기는 것을 줄이기 위한 조건이며, 1km/h 이상의 변화에는 추가 대기 시간을 넣지 않습니다. 응답 확인 시간 1초와 기존 페달·기어·신호 유효성 조건은 유지합니다.

새 기록에서 자동 RES/SET 후 순정 설정 속도가 요청 방향으로 바뀌는 사례와, 의도·panda 허용 송신 수가 같아도 순정 설정 속도가 그대로인 사례를 모두 확인했습니다. 목표 약 0.5km/h 경계의 미세 변동에서 한 프레임만 누른 뒤 해제되는 사례가 있어, 기존 코드의 무응답 잠금으로 이어지는 경로를 회귀 테스트로 재현했습니다. 미세 입력 방지는 이 원인만 다룹니다. 큰 목표 차이에서 한 번의 입력을 놓치면 영구 정지하던 경로는 제한된 재시도로 보완합니다. 최소 0.5초 간격으로 최대 세 번의 완전한 누름·해제만 허용하며, 모두 응답하지 않으면 기존처럼 차단합니다. 실제 차량 가감속 성능은 아직 검증되지 않았습니다.

진단 전환은 표준 cloudlog로 남기며 status/req/ack/noack, 목표·순정 설정 속도, blocked/fresh를 포함합니다. 원본 기록이나 위치·식별 정보는 게시하지 않습니다. 기존 C 안전 코드와 펌웨어는 변경하지 않았습니다.
