# 포터2 EV 일반 크루즈 버튼 제어 — 오프라인 검토용

2022년식 포터2 EV의 순정 일반 크루즈에서 목표 설정 속도에 따라
RES+/SET− 요청을 판단하는 독립적인 Python 프로토타입입니다.
**차량 설치용 패치가 아니며 CAN 송신, 자동 크루즈 활성화, 재출발,
브레이크 제어를 구현하지 않습니다.** openpilot 실행 경로에서 호출되지 않습니다.

## 실행 및 검증

저장소 루트에서 Python 표준 라이브러리만으로 실행합니다.

```sh
python -m unittest discover -s tools/porter_cruise_offline -v
```

합성 입력 테스트 9개가 통과했습니다. 실제 차량, panda safety, CAN 리플레이,
누름/해제 프로토콜 및 종방향 제어 성능은 검증하지 않았습니다.

## 판단 로직

`State`는 이미 검증·해석된 차량 입력을 받는 테스트용 자료형입니다.
`received_at`과 `now`는 같은 단조 시계를 사용해야 하며, 입력 전체가
신선하다는 것을 호출자가 확인해야 합니다. `valid`를 기본값으로 참으로
두거나 모르는 브레이크 상태를 거짓으로 입력해서는 안 됩니다.
주차브레이크/브레이크 홀드도 실제 어댑터에서는 브레이크 차단에 포함해야 합니다.

`ButtonDecider.update()`는 추상 문자열 `RES_ACCEL`, `SET_DECEL` 또는
`None`을 반환합니다. 목표 속도와 **순정 크루즈 설정 속도**를 비교합니다.
차량 현재 속도나 누른 횟수에 따른 추정값을 설정 속도 대신 사용하지 않습니다.

한 번 요청한 뒤 새 설정 속도가 요청한 방향으로 바뀌는 응답을 기다립니다.
요청 간격 제한, 응답 기한, 입력 만료, 활성 상태, D단, 정차, 페달,
운전자 버튼 및 오류 검사를 포함합니다. 이상 상태/운전자 개입/응답 실패는
명시적인 비활성화를 거칠 때까지 출력을 잠급니다. 테스트의 시간·속도 범위는
합성 입력용 숫자이며 포터용 권장 보정값이 아닙니다.

이 추상 이벤트를 곧바로 CAN 송신에 연결해서는 안 됩니다.
출력 문자열은 실제 메시지 송신 성공이나 차량의 물리적 반응을 의미하지 않습니다.

## 기존 코드 확인 결과

기준 커밋: `05c1678033c1c778f0386fba00c1e105bb26c427` (`c3-pht`).
아래 경로는 `opendbc_repo/opendbc/car/hyundai/` 기준입니다.

- `values.py:464`: `HYUNDAI_PORTER_II_EV`는 `EV | CC_ONLY_CAR`로 등록되어
  있으며 차량 문서 표기는 2024년식입니다. 2022년식의 신호 동일성을 증명하지 않습니다.
- `carcontroller.py:784`: `make_spam_button()`에 설정 속도 비교와 버튼 반복
  로직이 이미 있어 별도 송신 루프를 중복 추가할 필요가 없습니다.
- `carstate.py:561`: `CC_ONLY_CAR` 경로는 SCC의 활성/설정 속도 해석을 건너뛰며,
  이 함수에는 이를 대체하는 포터 전용 해석이 없습니다.
- `carstate.py:572`: 같은 플래그는 브레이크/주차브레이크 등의 해석도 건너뜁니다.
- `hyundaican.py:400`: CLU11 버튼 패커는 존재하지만 패커 존재만으로
  2022년식 포터의 버스·메시지·카운터·버튼 수락을 검증할 수는 없습니다.

## 실제 연동에 남은 작업

1. 해당 연식의 크루즈 활성, 실제 설정 속도, 브레이크/홀드/주차브레이크,
   물리 버튼 신호와 각 신호의 신선도를 확인합니다.
2. 실제 입력 신호를 어댑터에 연결하고 포터에 한정해 적용합니다.
3. 버튼 메시지, 버스, 카운터, 누름/해제, 응답 시간과 panda safety 허용을 검증합니다.
4. 운전자 취소, 브레이크 개입, 메시지 유실, 무응답 및 재활성화를 검증합니다.

일반 크루즈 설정 속도 감소를 브레이크 제동·차간거리 유지·정차 기능으로
간주하지 않습니다. 이 프로토타입의 테스트 통과는 차량 통합 완료를 의미하지 않습니다.
